Краткий ответ

`chmod` меняет маску прав (rwx для user/group/other), `chown` — владельца и группу. Хардлинк — ещё одна ссылка на тот же inode (одни данные, два имени); удаление одного имени не удаляет файл. Симлинк — отдельный файл, хранящий путь к цели; если цель удалена — симлинк «битый».


**chmod** принимает восьмеричную (`chmod 755 file`) или символьную (`chmod u+x,g-w file`) нотацию. Биты: r=4, w=2, x=1. Специальные биты: setuid (4000), setgid (2000), sticky (1000). Для директорий `x` = право на вход (traverse).

**chown**: `chown user:group file`; рекурсивно — `chown -R`. `chgrp` — только группу.

**Inode** хранит: тип файла, права, владелец/группа, размер, временны́е метки (atime/mtime/ctime), счётчик ссылок, указатели на блоки данных. Имя файла inode не хранит — оно живёт в directory entry.

**Хардлинк**: `ln src dst`. Оба имени указывают на один inode. `stat file` покажет `Links: 2`. Хардлинки нельзя делать на директории (предотвращает циклы) и нельзя пересекать ФС.

**Симлинк**: `ln -s target link`. Отдельный inode с типом `l`, содержимое — строка пути. Может пересекать ФС и указывать на директории. При удалении цели — dangling symlink.

```
ls -li          # i = inode number; одинаковый inode у хардлинков
stat file       # полные метаданные
readlink -f lnk # разрешить симлинк до реального пути
```

Ключевые тезисы

- Inode = метаданные (права, размер, блоки), но не имя файла
- Хардлинк — второе имя для того же inode; link count увеличивается
- Симлинк — отдельный файл с путём; может быть 'битым'
- Хардлинк нельзя создать для директории и через границу ФС
- `chmod 755` = rwxr-xr-x; `chmod +x` = только добавить execute
- `x` на директории = право войти; без него `ls` внутри не работает

Частые ошибки

- ✕Думать, что симлинк и хардлинк эквивалентны во всех случаях
- ✕Не знать, что хардлинки нельзя создать для директорий
- ✕Путать ctime (время изменения метаданных) и mtime (время изменения содержимого)
