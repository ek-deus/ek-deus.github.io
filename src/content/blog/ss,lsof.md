# DevOps #sobes
# linux #ss #lsof #zombie

Краткий ответ

Зомби (Z) — процесс завершён, но родитель не вызвал `wait()` — запись в таблице процессов есть, ресурсов нет. Осиротевший (orphan) — живой процесс, чей родитель умер; усыновляется PID 1 (systemd). Найти процесс на порту: `ss -tlnp sport = :8080` или `lsof -i :8080`.

**Zombie**: дочерний процесс вызвал `exit()`, ядро освободило ресурсы, но оставило запись в таблице процессов, пока родитель не заберёт exit code через `wait()`. Запись не занимает ни CPU, ни память — только PID из таблицы процессов. Тысячи зомби = баг в родителе (не вызывает `wait()`). Убить зомби напрямую нельзя — нужно убить или починить родителя.

**Orphan**: живой процесс, родитель которого завершился. Ядро переназначает родителя на PID 1 (systemd/init), который вызовет `wait()` при завершении orphan. Технически не проблема.

**Найти процесс на порту:**

```bash
ss -tlnp sport = :8080    # быстро, без root для своих процессов
lsof -i TCP:8080 -sTCP:LISTEN  # подробнее, PID + имя
fuser 8080/tcp            # только PID
# Если нужен root:
sudo ss -tlnp | grep :8080
```

**Убить:**

```bash
kill $(lsof -ti TCP:8080 -sTCP:LISTEN)
# или
fuser -k 8080/tcp
```

Ключевые тезисы

- Зомби: процесс мёртв, но родитель не забрал exit code; не занимает ресурсы кроме PID
- Orphan: живой процесс без родителя; усыновляется PID 1
- `ss -tlnp` — предпочтительный инструмент (быстрее netstat)
- `lsof -i :PORT` — видно имя процесса и PID
- Убить зомби нельзя — только починить/убить родителя

Частые ошибки

- ✕Путать зомби (мёртвый) и осиротевший (живой)
- ✕Использовать `netstat` вместо `ss` (устаревший, медленный)
- ✕Думать, что зомби занимают память/CPU
