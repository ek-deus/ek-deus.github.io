Netcat (`nc`) читает и записывает данные по TCP и UDP-соединениям. Одной небольшой утилитой удобно проверить порт, снять баннер сервиса, передать файл между машинами или собрать временный туннель. Ниже - типовые задачи и полезные приемы.

### Реализации Netcat

Реализаций Netcat несколько, и флаги у них различаются. По умолчанию встречаются:

* **OpenBSD netcat** - поставляется в Debian, Ubuntu (пакет `netcat-openbsd`), Fedora, Arch, Alpine. Примеры ниже рассчитаны на него;
* **Traditional (GNU) netcat** - старая реализация. В ней есть флаг `-e` для запуска программы при подключении, которого нет в OpenBSD-версии из соображений безопасности;
* **Ncat из пакета Nmap** - современная реализация с поддержкой TLS, прокси и обслуживанием нескольких клиентов одновременно.

Проверить свою версию и поддерживаемые опции:

```bash
nc -h
```

### Проверка портов и сервисов

Обычный `ping` использует ICMP и не показывает, открыт ли нужный сервис. Netcat проверяет именно сетевое соединение:

```bash
nc -zv -w 3 example.ru 80 443 22
```

* `-z` - режим сканирования (не передавать данные);
* `-v` - подробный вывод (verbose);
* `-w 3` - таймаут ожидания соединения (3 секунды).

#### Сканирование диапазонов портов

Netcat можно использовать как легкую альтернативу Nmap, когда последний недоступен:

```bash
nc -zv -w 1 192.0.2.10 20-80
```

#### Проверка UDP-портов

По умолчанию Netcat работает по протоколу TCP. Для диагностики UDP-сервисов (DNS, NTP, Syslog) добавляется флаг `-u`:

```bash
nc -zuv -w 3 192.0.2.10 53
```

> **Нюанс:** UDP - протокол без установления соединения. Флаг `-z` для UDP может дать ложноположительный результат (*«succeeded!»*), если фаервол просто тихо сбрасывает пакеты (DROP). Для точной проверки UDP-сервиса лучше передать реальный запрос.

#### Снять баннер сервиса

Для получения ответа сервиса отправляется запрос с правильными разделителями строк CRLF (`\r\n`) и заголовком `Host`:

```bash
printf 'HEAD / HTTP/1.0\r\nHost: example.ru\r\n\r\n' | nc -N -w 3 example.ru 80
```

* `-N` - автоматически закрывает сокет на отправку при достижении EOF (конца ввода в stdin). Это предотвращает «зависание» `nc` в скриптах и автоматизациях *(в GNU-версии вместо `-N` используется `-q 0`)*.

### Передача файлов между машинами

Когда под рукой нет `scp` или `rsync`.

**На принимающей стороне (сервер):**

```bash
nc -l -p 9899 > backup.iso
```

* `-l` - режим прослушивания (listen);
* `-p 9899` - указание порта.

**На отправляющей стороне (клиент):**

```bash
nc 192.0.2.10 9899 < backup.iso
```

Netcat не шифрует данные и не проверяет их целостность, поэтому передавать так файлы стоит только внутри доверенной сети.

#### Сжатие и отображение прогресса

Для больших файлов данные сжимают на лету, а с помощью утилиты `pv` (Pipe Viewer) отслеживают скорость и объем передачи:

```bash
# На стороне приёма:
nc -l -p 9899 | gzip -dc > backup.iso

# На стороне отправки (с индикатором прогресса):
pv backup.iso | gzip -c | nc 192.0.2.10 9899
```

После передачи обязательно сверьте контрольную сумму (`sha256sum`) на обеих сторонах.

### Простейший HTTP-сервер для отладки

Если нужно быстро проверить, доходят ли HTTP-запросы (например, Webhook) через фаервол или балансировщик, можно развернуть заглушку с помощью флага `-k` (прослушивание нескольких подключений подряд):

```bash
while true; do
  echo -e "HTTP/1.1 200 OK\r\nContent-Length: 2\r\n\r\nOK" | nc -kl -p 8080
done
```

### Временный TCP-туннель

Пробросить локальный порт на внутренний сервис можно через именованный канал (`fifo`):

```bash
mkfifo /tmp/backpipe
nc -l 8080 < /tmp/backpipe | nc db.internal 5432 > /tmp/backpipe
```

Теперь подключение к локальному порту `8080` перенаправляется на внутренний сервер PostgreSQL (`5432`). Это разовое незашифрованное решение для отладки; для постоянного и безопасного доступа используют SSH-туннели или VPN.

### Когда Netcat не хватает

* **Ncat** (из пакета `nmap`) - поддерживает TLS-шифрование, прокси, обработку нескольких клиентов и флаг `--exec`;
* **socat** - двунаправленная передача данных между любыми источниками (сокеты, файлы, устройства, TLS-сертификаты). Имеет более сложный синтаксис, но выигрывает в функциональности.

Установка дополнительных утилит в Debian/Ubuntu:

```bash
sudo apt install nmap socat pv
```

### Как защититься от Netcat в чужих руках

Те же свойства делают Netcat популярным инструментом атакующего: получив доступ к серверу, злоумышленник может открыть обратное соединение (reverse shell) наружу, чтобы обойти входящий межсетевой экран.

Меры снижения риска:

1. **Фильтруйте исходящий трафик.** По умолчанию серверы часто выпускают любые соединения наружу. Ограничьте исходящие порты только необходимыми направлениями:
```bash
# Только DNS, HTTP и HTTPS наружу, остальное - запрет
ufw default deny outgoing
ufw allow out 53
ufw allow out 80
ufw allow out 443
```


2. **Минимизируйте ПО на сервере.** Не держите `netcat`, компиляторы и лишние интерпретаторы на боевых серверах без необходимости.
3. **Следите за подозрительными процессами.** Исходящее сетевое соединение от `nc`, `bash` или `sh` на внешний адрес - повод для расследования:

```bash
ss -tnp | grep -E 'nc|bash|sh'
```


1. **Настройте аудит.** Правило `auditd` позволит фиксировать создание именованных каналов (`mkfifo`, `mknod`) - типичный признак обратной оболочки без флага `-e`:

```bash
auditctl -a always,exit -F arch=b64 -S mknod -S mknodat -k reverse_shell
```

Полноценно такие атаки ловят системы обнаружения вторжений на хосте (Auditd с готовыми правилами, Falco, EDR) - они видят аномальные связки «командный интерпретатор + сетевое соединение».

#### Итог

Netcat перекладывает байты из `stdin` в сеть и обратно, благодаря чему отлично сочетается с утилитами Linux-окружения (`gzip`, `dd`, `pv`, пайпы). Для быстрой проверки портов, разовой передачи файлов и временных туннелей этого достаточно; для защищенных и постоянных сервисов лучше использовать Ncat, socat, SSH или VPN.
