Разница между **жесткой ссылкой (Hard Link)** и **символьной ссылкой (Symbolic Link / Symlink)** заключается в том, _на что именно_ указывает ссылка на уровне структуры файловой системы (inodes).

В Unix-подобных системах (Linux, macOS) любой файл состоит из двух частей:

1. **Данные** на диске (блоки с содержимым).

2. **Индексный дескриптор (inode)** — метаданные файла (размер, владельцы, права доступа и координаты блоков с данными на диске). Имя файла хранится в директории и ссылается на конкретный `inode`.

### 1. Жесткая ссылка (Hard Link)

**Жесткая ссылка** — это дополнительное имя для уже существующего `inode`.

При создании жесткой ссылки новый файл не создается: создается лишь еще одна запись в файловой структуре, указывающая на **тот же самый `inode`**.

```Plaintext
Имя файла A  ─────┐
                  ├───>  [ inode #12345 ]  ───>  [ Данные на диске ]
Имя файла B  ─────┘    (счетчик ссылок = 2)
 (Hard Link)
```

#### Ключевые особенности жестких ссылок

- **Один и тот же файл:** Оба файла (оригинал и ссылка) абсолютно равны. Изменение содержимого через один файл моментально отражается в другом.

- **Удаление оригинала:** Если удалить исходный файл, данные **не пропадут**. Ссылка продолжит работать, так как счетчик ссылок в `inode` станет равным 1 (данные стираются только когда счетчик ссылок `inode` становится равен 0).

- **Права доступа:** Права, владельцы и размер у всех жестких ссылок одинаковы, так как они читаются из одного `inode`.

- **Ограничения:**

  - Нельзя создавать жесткие ссылки на **директории** (чтобы избежать циклов в файловой системе).

  - Нельзя делать жесткие ссылки **между разными файловыми системами/разделами** (так как нумерация `inode` уникальна только в рамках одного раздела).

### 2. Символьная ссылка (Symlink / Soft Link)

**Символьная ссылка** — это отдельный специальный файл, который содержит в себе текстовый **путь к целевому файлу** (аналог «ярлыка» в Windows).

У нее создается собственный `inode` и собственные блоки данных.

```Plaintext
Имя файла A   ───>  [ inode #12345 ]  ───>  [ Данные на диске ]
                          ▲
                          │ (содержит путь "/path/to/A")
                          │
Symlink B     ───>  [ inode #67890 ]
```

#### Ключевые особенности символьных ссылок

- **Удаление оригинала:** Если удалить оригинальный файл, символьная ссылка ломается (**битая ссылка / Broken Symlink**). Она продолжит указывать на несуществующий путь.

- **Гибкость:**

  - Можно ссылаться на **директории**.

  - Можно указывать на файлы и папки **в других файловых системах, дисках или монтированиях**.

- **Размер:** Размер символьной ссылки равен длине текстовой строки пути, который в ней записан (в байтах).

### Сравнительная таблица

|**Критерий**|**Жесткая ссылка (Hard Link)**|**Символьная ссылка (Symlink)**|
|---|---|---|
|**Что из себя представляет**|Еще одно имя для одного и того же `inode`.|Отдельный файл со ссылкой на путь другого файла.|
|**Удаление исходного файла**|Данные сохраняются, ссылка остается рабочей.|Ссылка ломается (указывает в пустоту).|
|**Указание на директории**|**Нет** (запрещено в большинстве ОС).|**Да**.|
|**Пересечение разделов диска**|**Нет** (только внутри одной ФС).|**Да** (между разными дисками и ФС).|
|**Занимаемое место**|0 дополнительного места на диске.|Несколько байт (длина строки пути).|
|**Команда создания в Linux**|`ln file.txt hardlink.txt`|`ln -s file.txt symlink.txt`|

Вот практические примеры работы с жесткими и символьными ссылками в Linux с использованием команд `ln`, `ls` и `stat`.

### Подготовка: Создаем исходный файл

Сначала создадим папку для экспериментов и тестовый файл:

```Bash
mkdir /tmp/links_demo && cd /tmp/links_demo
echo "Hello, Linux!" > original.txt
```

### 1. Жесткая ссылка (Hard Link)

Создается командой `ln` без дополнительных флагов.

#### Создание ссылки

```Bash
ln original.txt hardlink.txt
```

#### Проверка через `stat` и `ls`

Запустим команду `stat` для обоих файлов:

```Bash
stat original.txt hardlink.txt
```

**Вывод:**

```Plaintext
  File: original.txt
  Size: 14         Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d Inode: 123456      Links: 2
...
  File: hardlink.txt
  Size: 14         Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d Inode: 123456      Links: 2
```

> **На что обратить внимание:**
>
> 1. Номера **`Inode` совпадают** (`123456`). Это один и тот же файл под разными именами.
>
> 2. Счетчик **`Links: 2`** покажет, что у этого `inode` теперь 2 имени в файловой системе.
>

#### Проверка независимости от оригинала

Удалим исходный файл `original.txt` и проверим, что данные сохранились:

```Bash
rm original.txt

# Файл hardlink.txt продолжает работать:
cat hardlink.txt
# Вывод: Hello, Linux!

# Проверяем количество ссылок у оставшегося файла:
stat hardlink.txt | grep Links
# Вывод: Device: 801h/2049d  Inode: 123456  Links: 1
```

### 2. Символьная ссылка (Symlink / Soft Link)

Создается командой `ln -s`.

#### Создание ссылки

Восстановим исходный файл и создадим символьную ссылку:

```Bash
echo "Hello again!" > original.txt
ln -s original.txt symlink.txt
```

#### Проверка через `ls -l` и `stat`

Выполним детальный просмотр каталога:

```Bash
ls -l
```

**Вывод:**

```Plaintext
lrwxrwxrwx 1 user group 12 Aug 24 10:56 symlink.txt -> original.txt
-rw-r--r-- 1 user group 13 Aug 24 10:56 original.txt
```

_(Тип файла `l` говорит о том, что это symbolic link, а стрелочка `->` указывает на целевой файл)._

Теперь посмотрим вывод `stat` для символьной ссылки:

```Bash
stat symlink.txt
```

**Вывод:**

```Plaintext
  File: symlink.txt -> original.txt
  Size: 12         Blocks: 0          IO Block: 4096   symbolic link
Device: 801h/2049d Inode: 999999      Links: 1
```

> **На что обратить внимание:**
>
> 1. У `symlink.txt` свой собственный уникальный **`Inode: 999999`** (отличный от `original.txt`).
>
> 2. Размер файла **`Size: 12`** — это ровно количество символов в строке-пути `"original.txt"`.
>

#### Поведение при удалении оригинала («битая» ссылка)

Удалим исходный файл:

```Bash
rm original.txt

# Попытка прочесть файл выдаст ошибку:
cat symlink.txt
# Вывод: cat: symlink.txt: No such file or directory
```

В выводе `ls --color` сломанная символьная ссылка будет подсвечена красным цветом.

### 3. Символьная ссылка на директорию

В отличие от жестких ссылок, символьные ссылки легко работают с папками:

```Bash
mkdir -p /var/log/my_app
ln -s /var/log/my_app ./app_logs

# Навигация по ссылке:
cd app_logs
pwd -P # Покажет реальный физический путь: /var/log/my_app
```

### Чек-лист главных команд

|**Задача**|**Команда**|
|---|---|
|**Создать жесткую ссылку**|`ln target_file hard_link_name`|
|**Создать символьную ссылку**|`ln -s target_file symlink_name`|
|**Посмотреть Inode файлов**|`ls -i` или `stat filename`|
|**Найти все жесткие ссылки на файл**|`find / -samefile original.txt`|
|**Узнать, куда ведет symlink**|`readlink -f symlink_name`|
